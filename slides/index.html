What is an agent · 6

5

Agent

Tools in a loop, until the goal is reached.

“An LLM agent runs tools in a loop to achieve a goal.”

Simon Willison, 2025

1

Works toward a goal

It has a stopping point: the goal is reached.

2

Gets closer step by step

Each turn uses the results of the last one.

3

Uses tools

It acts: runs code, reads files, searches.

There is no official definition. ISO/IEC 22989: an agent perceives its environment and acts to reach goals.

A naive agent raises questions:

?

?

Delete a file? Send an email? Spend money?

?

What controls the loop?

When to stop, how many turns, what it costs.

→ The answer is the harness.

THE WHOLE LOOP, IN CODE

An agent is a model, a loop and tools

PYTHON, SIMPLIFIED

messages = [user(task)]

while True:
    reply = model(messages, tools=TOOLS)
    messages.append(reply)

    if not reply.tool_calls:
        break

    for call in reply.tool_calls:
        if allowed(call):
            result = run(call)
        else:
            result = "permission denied"
        messages.append(tool_result(call.id, result))


print(reply.text)

1

Call the model

With the whole conversation and the tool list. Save its reply.

2

No tool request? Stop.

The model decides when the work is done.

3

Run the tools

Check the permission first. Add each result to the conversation.

4

Repeat

Back to the model, with the results.

“It’s an LLM, a loop, and enough tokens.” A full coding agent: less than 400 lines. Thorsten Ball, “How to Build an Agent”, ampcode.com, 2025

MCP · PROBLEM · 2025

Problem: many calls, big results

Task: the model counted the Goldbach partitions of 1,000 even numbers. Which OEIS sequence is this?

Each tool call is one round trip. Every result goes into the context.

Finding tools is cheaper now. Moving their results is still expensive.

Goldbach partition of n: a way to write n as a sum of two primes. Example: 10 = 3 + 7 = 5 + 5, so 10 has 2 partitions.

Same pattern, estimated: in Anthropic’s Drive → Salesforce example, a long transcript could add ~50k tokens (“Code execution with MCP”, Nov 2025).

MCP · FIX · Sep 2025 · Nov 2026

Fix: Code Mode, the model writes code

CODE WRITTEN BY THE MODEL · ONE PROGRAM, 51 TOOL CALLS

const ids = await oeis.search_sequences("goldbach");
for (const id of ids) {
  const t = await oeis.get_terms(id, 1000);
  if (matches(t, myCounts)) console.log(id);
}
// → A002375

A sandbox runs it. The 50,000 numbers stay in the sandbox, and the code compares them exactly. Only “A002375” reaches the model.

WHY CODE?

1. Models write code well.

They learned from millions of real programs. They saw few tool calls.

2. RL trains the tool use.

Tools are just functions. Code can be run and checked, so labs can train the model on it with RL.

TOOLS, IN DETAIL

How a tool call works

1

Model asks

The reply holds a structured tool request.

{
  "tool_call": {
    "id": "call_1",
    "name": "bash",
    "arguments": {
      "command":
      "python goldbach.py"
    }
  }
}

2

Harness runs it

Check the permission. Run the tool, locally or remotely.

$ python goldbach.py

{"checked": 498,
 "counterexamples": []}

3

Result goes back

The harness adds it to the conversation.

{
  "role": "tool",
  "tool_call_id":
    "call_1",
  "content":
    "{checked: 498 …}"
}

4

Model again

Same conversation, plus the result. Now it can answer.

“Yes. All 498 even numbers pass.”

no tool call → done

new tool call → step 2

The model never runs anything. It writes a request. The harness does the work.

1.3M views on X

“That’s not a confidence problem I can fix by believing harder. […] I won’t report RH as solved […] unless there’s a proof that survives […] review.”
